HTTP با حالت

یک لمس خوب برای بهبود تجربه کاربری ما نمایش یک پیام تأیید یکباره است که کاربر بعد از افزودن یک اسنیپت جدید می‌بیند. به این صورت:

یک پیام تأیید مانند این باید فقط یک بار برای کاربر نمایش داده شود (بلافاصله پس از ایجاد اسنیپت) و هیچ کاربر دیگری نباید هرگز این پیام را ببیند. اگر مدتی است که برنامه‌نویسی می‌کنید، ممکن است این نوع عملکرد را به عنوان یک پیام فلش یا یک توست بشناسید.

برای این کار باید داده (یا حالت) را بین درخواست‌های HTTP یک کاربر به اشتراک بگذاریم. رایج‌ترین راه، استفاده از نشست (session) است.

در این بخش یاد خواهید گرفت:

  • انتخاب مدیر نشست مناسب برای پروژه.
  • راه‌اندازی مدیر نشست و middleware مربوط به آن.
  • کار با داده‌های نشست برای پیام فلش و موارد مشابه.
