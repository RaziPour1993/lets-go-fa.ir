# فصل 9.5.

## تنظیمات HTTPS

<div dir='rtl'>Go تنظیمات پیش‌فرض خوبی برای سرور HTTPS خود دارد، اما می‌توان نحوه عملکرد سرور را بهینه و سفارشی کرد.</div>

<div dir='rtl'>یکی از تغییراتی که تقریباً همیشه ایده خوبی است، محدود کردن منحنی‌های بیضوی است که می‌توانند در طول دست دادن TLS استفاده شوند. Go از چند منحنی بیضوی پشتیبانی می‌کند، اما از نسخه Go 1.23 تنها tls.CurveP256 و tls.X25519 پیاده‌سازی‌های اسمبلی دارند. بقیه بسیار پردازش‌بر هستند، بنابراین حذف آنها کمک می‌کند تا سرور ما تحت بارهای سنگین عملکرد خوبی داشته باشد.</div>

<div dir='rtl'>برای انجام این تغییر، می‌توانیم یک ساختار tls.Config حاوی تنظیمات TLS غیرپیش‌فرض خود ایجاد کنیم و آن را به ساختار http.Server خود اضافه کنیم قبل از اینکه سرور را شروع کنیم.</div>

<div dir='rtl'>من نشان خواهم داد:</div>

<div dir='ltr'>

**File:  cmd/web/main.go**

```

package main

import (
    "crypto/tls" // New import
    "database/sql"
    "flag"
    "html/template"
    "log/slog"
    "net/http"
    "os"
    "time"

    "snippetbox.alexedwards.net/internal/models"

    "github.com/alexedwards/scs/mysqlstore"
    "github.com/alexedwards/scs/v2"
    "github.com/go-playground/form/v4"
    _ "github.com/go-sql-driver/mysql"
)

...

func main() {
    ...

    app := &application{
        logger:         logger,
        snippets:       &models.SnippetModel{DB: db},
        templateCache:  templateCache,
        formDecoder:    formDecoder,
        sessionManager: sessionManager,
    }

    // Initialize a tls.Config struct to hold the non-default TLS settings we
    // want the server to use. In this case the only thing that we're changing
    // is the curve preferences value, so that only elliptic curves with
    // assembly implementations are used.
    tlsConfig := &tls.Config{
        CurvePreferences: []tls.CurveID{tls.X25519, tls.CurveP256},
    }

    // Set the server's TLSConfig field to use the tlsConfig variable we just
    // created.
    srv := &http.Server{
        Addr:      *addr,
        Handler:   app.routes(),
        ErrorLog:  slog.NewLogLogger(logger.Handler(), slog.LevelError),
        TLSConfig: tlsConfig,
    }

    logger.Info("starting server", "addr", srv.Addr)

    err = srv.ListenAndServeTLS("./tls/cert.pem", "./tls/key.pem")
    logger.Error(err.Error())
    os.Exit(1)
}

...
```

### اطلاعات اضافی

#### نسخه‌های TLS

<div dir='rtl'>به طور پیش‌فرض، سرور HTTPS Go برای پشتیبانی از TLS 1.2 و 1.3 پیکربندی شده است. می‌توانید این را سفارشی کنید و حداقل و حداکثر نسخه‌های TLS را با استفاده از فیلدهای tls.Config.MinVersion و MaxVersion و ثابت‌های نسخه‌های TLS در بسته crypto/tls تغییر دهید.</div>

<div dir='rtl'>برای مثال، اگر می‌خواهید سرور فقط از نسخه‌های TLS 1.0 تا 1.2 پشتیبانی کند، می‌توانید از پیکربندی زیر استفاده کنید:</div>

#### مجموعه‌های رمزنگاری

<div dir='rtl'>مجموعه‌های رمزنگاری که Go پشتیبانی می‌کند نیز در ثابت‌های بسته crypto/tls تعریف شده‌اند.</div>

<div dir='rtl'>با این حال، برخی از این مجموعه‌های رمزنگاری (به طور خاص، مجموعه‌های رمزنگاری که از Perfect Forward Secrecy پشتیبانی نمی‌کنند، یا از RC4، 3DES یا CBC_SHA256 استفاده می‌کنند) ضعیف در نظر گرفته می‌شوند و به طور پیش‌فرض توسط سرور HTTPS Go استفاده نمی‌شوند. از نسخه Go 1.23، مجموعه‌های رمزنگاری که به طور پیش‌فرض توسط سرور HTTPS Go استفاده می‌شوند عبارتند از:</div>

<div dir='rtl'>مهم: به دلایل سازگاری با مشتری، این لیست پیش‌فرض شامل برخی از رمزهای CBC است که به حملات زمانی Lucky Thirteen آسیب‌پذیر هستند. پیاده‌سازی Go از این پچ شده است تا برخی — اما نه کامل — کاهش در برابر حملات احتمالی را فراهم کند .</div>

<div dir='rtl'>اگر می‌خواهید مجموعه‌های رمزنگاری استفاده شده توسط سرور HTTPS Go را تغییر دهید — یا با اضافه کردن مجموعه‌های رمزنگاری ضعیفی که به طور پیش‌فرض استفاده نمی‌شوند، یا حذف برخی از رمزهایی که به طور پیش‌فرض استفاده می‌شوند — می‌توانید این کار را از طریق فیلد tls.Config.CipherSuites انجام دهید.</div>

<div dir='rtl'>برای مثال، اگر می‌خواهید از لیست پیش‌فرض رمزها استفاده کنید اما با حذف رمزهای CBC، می‌توانید tls.Config خود را به این صورت پیکربندی کنید:</div>

<div dir='rtl'>Go به طور خودکار انتخاب می‌کند کدام از این مجموعه‌های رمزنگاری در زمان اجرا استفاده شود بر اساس امنیت رمز، عملکرد و پشتیبانی سخت‌افزار مشتری/سرور.</div>

<div dir='rtl'>همچنین مهم (و جالب) است که توجه داشته باشید که اگر یک اتصال TLS 1.3 مذاکره شود، tls.Config.CipherSuites نادیده گرفته می‌شود. دلیل این امر این است که همه مجموعه‌های رمزنگاری که Go برای اتصالات TLS 1.3 پشتیبانی می‌کند به عنوان ایمن در نظر گرفته می‌شوند، بنابراین ارائه مکانیزمی برای پیکربندی آنها چندان منطقی نیست.</div>

<div dir='rtl'>به طور اساسی، استفاده از tls.Config.CipherSuites برای تنظیم یک لیست سفارشی از مجموعه‌های رمزنگاری پشتیبانی شده فقط بر اتصالات TLS 1.0-1.2 تأثیر می‌گذارد. بنابراین، در مثال بالا، در واقع نیازی به شامل کردن رمزهای خاص TLS 1.3 نیست و می‌توان آن را به این صورت ساده کرد:</div>

<div dir='rtl'>مهم: محدود کردن مجموعه‌های رمزنگاری پشتیبانی شده می‌تواند به این معنا باشد که کاربران با برخی مرورگرهای قدیمی‌تر نمی‌توانند از وب‌سایت شما استفاده کنند. تعادلی بین امنیت و سازگاری با گذشته وجود دارد و تصمیم درست برای شما به فناوری‌هایی که معمولاً توسط کاربران شما استفاده می‌شود بستگی دارد. پیکربندی‌های پیشنهادی موزیلا برای مرورگرهای مدرن، متوسط و قدیمی ممکن است به شما در تصمیم‌گیری کمک کند.</div>
