## تجزیه داده‌های فرم

<div dir='rtl'>با توجه به کاری که قبلاً در بخش پایه‌ها انجام دادیم، هر درخواست POST /snippets/create به هندلر snippetCreatePost ما ارسال می‌شود. اکنون این هندلر را به‌روزرسانی می‌کنیم تا داده‌های فرم را هنگام ارسال پردازش و استفاده کند.</div>

<div dir='rtl'>در سطح بالا، می‌توانیم این را به دو مرحله مجزا تقسیم کنیم.</div>

<div dir='rtl'>ابتدا، باید از متد r.ParseForm() برای تجزیه بدنه درخواست استفاده کنیم. این بررسی می‌کند که بدنه درخواست به درستی شکل گرفته است، و سپس داده‌های فرم را در نقشه r.PostForm درخواست ذخیره می‌کند. اگر هنگام تجزیه بدنه خطایی رخ دهد (مانند عدم وجود بدنه، یا خیلی بزرگ بودن آن برای پردازش) یک خطا برمی‌گرداند. متد r.ParseForm() همچنین ایدمپوتنت است؛ می‌تواند چندین بار روی یک درخواست یکسان بدون هیچ عوارض جانبی فراخوانی شود.</div>

<div dir='rtl'>سپس می‌توانیم به داده‌های فرم موجود در r.PostForm با استفاده از متد r.PostForm.Get() دسترسی پیدا کنیم. به عنوان مثال، می‌توانیم مقدار فیلد title را با r.PostForm.Get("title") بازیابی کنیم. اگر هیچ فیلد منطبقی در فرم وجود نداشته باشد، رشته خالی "" را برمی‌گرداند.</div>

<div dir='rtl'>فایل cmd/web/handlers.go خود را باز کنید و آن را با کد زیر به‌روزرسانی کنید:</div>

<div dir='ltr'>

**File: cmd/web/handlers.go**

```

package main

...

func (app *application) snippetCreatePost(w http.ResponseWriter, r *http.Request) {
    // First we call r.ParseForm() which adds any data in POST request bodies
    // to the r.PostForm map. This also works in the same way for PUT and PATCH
    // requests. If there are any errors, we use our app.ClientError() helper to 
    // send a 400 Bad Request response to the user.
    err := r.ParseForm()
    if err != nil {
        app.clientError(w, http.StatusBadRequest)
        return
    }

    // Use the r.PostForm.Get() method to retrieve the title and content
    // from the r.PostForm map.
    title := r.PostForm.Get("title")
    content := r.PostForm.Get("content")

    // The r.PostForm.Get() method always returns the form data as a *string*.
    // However, we're expecting our expires value to be a number, and want to
    // represent it in our Go code as an integer. So we need to manually convert
    // the form data to an integer using strconv.Atoi(), and we send a 400 Bad
    // Request response if the conversion fails.
    expires, err := strconv.Atoi(r.PostForm.Get("expires"))
    if err != nil {
        app.clientError(w, http.StatusBadRequest)
        return
    }

    id, err := app.snippets.Insert(title, content, expires)
    if err != nil {
        app.serverError(w, r, err)
        return
    }

    http.Redirect(w, r, fmt.Sprintf("/snippet/view/%d", id), http.StatusSeeOther)
}

```

### اطلاعات تکمیلی

#### متد PostFormValue

<div dir='rtl'>پکیج net/http همچنین متد r.PostFormValue() را ارائه می‌دهد، که اساساً یک تابع میانبر است که r.ParseForm() را برای شما فراخوانی می‌کند و سپس مقدار فیلد مناسب را از r.PostForm بازیابی می‌کند.</div>

<div dir='rtl'>توصیه می‌کنم از این میانبر استفاده نکنید زیرا هر خطایی که توسط r.ParseForm() برگردانده می‌شود را به صورت خاموش نادیده می‌گیرد. اگر از آن استفاده کنید، به این معنی است که مرحله تجزیه ممکن است با خطا مواجه شود و برای کاربران شکست بخورد، اما هیچ مکانیزم بازخوردی برای اطلاع دادن به آنها (یا شما) درباره مشکل وجود ندارد.</div>

#### محدود کردن اندازه فرم

<div dir='rtl'>به طور پیش‌فرض، فرم‌هایی که با متد POST ارسال می‌شوند محدودیت اندازه ۱۰ مگابایت داده دارند. استثنا این است که اگر فرم شما ویژگی enctype="multipart/form-data" داشته باشد و داده‌های چندبخشی ارسال کند، در این صورت هیچ محدودیت پیش‌فرضی وجود ندارد.</div>

<div dir='rtl'>اگر می‌خواهید محدودیت ۱۰ مگابایت را تغییر دهید، می‌توانید از تابع http.MaxBytesReader() به این صورت استفاده کنید:</div>

<div dir='rtl'>با این کد تنها ۴۰۹۶ بایت اول بدنه درخواست در طول r.ParseForm() خوانده خواهد شد. تلاش برای خواندن فراتر از این محدودیت باعث می‌شود MaxBytesReader یک خطا برگرداند، که متعاقباً توسط r.ParseForm() نمایش داده می‌شود.</div>

<div dir='rtl'>علاوه بر این - اگر به محدودیت برخورد شود - MaxBytesReader یک پرچم روی http.ResponseWriter تنظیم می‌کند که به سرور دستور می‌دهد اتصال TCP زیربنایی را ببندد.</div>

#### پارامترهای رشته پرس‌وجو

<div dir='rtl'>اگر فرمی دارید که داده‌ها را با استفاده از متد HTTP GET، به جای POST ارسال می‌کند، داده‌های فرم به عنوان پارامترهای رشته پرس‌وجو URL گنجانده خواهند شد. به عنوان مثال، اگر یک فرم HTML به این شکل داشته باشید:</div>

<div dir='rtl'>هنگامی که فرم ارسال می‌شود، یک درخواست GET با URL به این شکل ارسال خواهد کرد: /foo/bar?title=value&content=value.</div>

<div dir='rtl'>می‌توانید مقادیر پارامترهای رشته پرس‌وجو را در هندلرهای خود از طریق متد r.URL.Query().Get() بازیابی کنید. این همیشه یک مقدار رشته‌ای برای یک پارامتر برمی‌گرداند، یا رشته خالی "" اگر هیچ پارامتر منطبقی وجود نداشته باشد. به عنوان مثال:</div>

#### نقشه r.Form

<div dir='rtl'>روش جایگزین برای دسترسی به پارامترهای رشته پرس‌وجو از طریق نقشه r.Form است. این مشابه نقشه r.PostForm است که در این فصل استفاده کردیم، با این تفاوت که شامل داده‌های فرم از هر بدنه درخواست POST و هر پارامتر رشته پرس‌وجو است.</div>

<div dir='rtl'>فرض کنید کدی در هندلر خود به این شکل دارید:</div>

<div dir='rtl'>در این کد، خط r.Form.Get("title") مقدار title را از بدنه درخواست POST یا از یک پارامتر رشته پرس‌وجو با نام title برمی‌گرداند. در صورت تعارض، مقدار بدنه درخواست بر پارامتر رشته پرس‌وجو اولویت دارد.</div>

<div dir='rtl'>استفاده از r.Form می‌تواند بسیار مفید باشد اگر می‌خواهید برنامه شما نسبت به نحوه ارسال مقادیر داده بی‌تفاوت باشد. اما خارج از آن سناریو، r.Form هیچ مزیتی ارائه نمی‌دهد و واضح‌تر و صریح‌تر است که داده‌ها را از بدنه درخواست POST از طریق r.PostForm یا از پارامترهای رشته پرس‌وجو از طریق r.URL.Query().Get() بخوانید.</div>
