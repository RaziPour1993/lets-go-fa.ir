# فصل ۶.۲

## تنظیم هدرهای مشترک

<div dir='rtl'>بیایید از الگویی که در فصل قبل آموختیم استفاده کنیم و میان‌افزاری بسازیم که به طور خودکار هدر Server: Go را به همراه هدرهای امنیتی HTTP زیر (مطابق با راهنمای فعلی OWASP) به هر پاسخ اضافه کند.</div>

<div dir='rtl'>اگر با این هدرها آشنا نیستید، به سرعت توضیح می‌دهم که چه کاری انجام می‌دهند.</div>

<div dir='rtl'>هدرهای Content-Security-Policy (که اغلب به اختصار CSP نامیده می‌شوند) برای محدود کردن منابعی که صفحه وب شما می‌تواند از آنها بارگذاری شود (مانند جاوااسکریپت، تصاویر، فونت‌ها و غیره) استفاده می‌شوند. تنظیم یک سیاست سختگیرانه CSP به جلوگیری از انواع حملات cross-site scripting، clickjacking و سایر حملات تزریق کد کمک می‌کند.</div>

<div dir='rtl'>هدرهای CSP و نحوه کار آنها موضوع بزرگی است، و اگر قبلاً با آنها برخورد نکرده‌اید، پیشنهاد می‌کنم این مقدمه را بخوانید. اما در مورد ما، هدر به مرورگر می‌گوید که بارگیری فونت‌ها از fonts.gstatic.com، استایل‌شیت‌ها از fonts.googleapis.com و self (منشأ خودمان)، و سپس همه چیز دیگر فقط از self مجاز است. جاوااسکریپت درون‌خطی به طور پیش‌فرض مسدود می‌شود.</div>

<div dir='rtl'>Referrer-Policy برای کنترل اطلاعاتی که در هدر Referer هنگام خروج کاربر از صفحه وب شما گنجانده می‌شود، استفاده می‌شود. در مورد ما، ما مقدار را روی origin-when-cross-origin تنظیم می‌کنیم، که به این معنی است که URL کامل برای درخواست‌های same-origin گنجانده خواهد شد، اما برای همه درخواست‌های دیگر، اطلاعاتی مانند مسیر URL و مقادیر رشته پرس‌وجو حذف خواهند شد.</div>

<div dir='rtl'>X-Content-Type-Options: nosniff به مرورگرها دستور می‌دهد که content-type پاسخ را MIME-type sniff نکنند، که به نوبه خود به جلوگیری از حملات content-sniffing کمک می‌کند.</div>

<div dir='rtl'>X-Frame-Options: deny برای کمک به جلوگیری از حملات clickjacking در مرورگرهای قدیمی‌تر که از هدرهای CSP پشتیبانی نمی‌کنند، استفاده می‌شود.</div>

<div dir='rtl'>X-XSS-Protection: 0 برای غیرفعال کردن مسدود کردن حملات cross-site scripting استفاده می‌شود. قبلاً تنظیم این هدر به X-XSS-Protection: 1; mode=block یک عمل خوب بود، اما وقتی از هدرهای CSP مانند ما استفاده می‌کنید، توصیه این است که این ویژگی را کاملاً غیرفعال کنید.</div>

<div dir='rtl'>خب، بیایید به کد Go خود برگردیم و با ایجاد یک فایل جدید middleware.go شروع کنیم. ما از این برای نگهداری تمام میان‌افزارهای سفارشی که در طول این کتاب می‌نویسیم استفاده خواهیم کرد.</div>

<div dir='rtl'>سپس آن را باز کنید و یک تابع commonHeaders() با استفاده از الگویی که در فصل قبل معرفی کردیم اضافه کنید:</div>

<div dir='ltr'>

**File: cmd/web/middleware.go**

```

package main

import (
    "net/http"
)

func commonHeaders(next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        // Note: This is split across multiple lines for readability. You don't 
        // need to do this in your own code.
        w.Header().Set("Content-Security-Policy",
            "default-src 'self'; style-src 'self' fonts.googleapis.com; font-src fonts.gstatic.com")

        w.Header().Set("Referrer-Policy", "origin-when-cross-origin")
        w.Header().Set("X-Content-Type-Options", "nosniff")
        w.Header().Set("X-Frame-Options", "deny")
        w.Header().Set("X-XSS-Protection", "0")

        w.Header().Set("Server", "Go")

        next.ServeHTTP(w, r)
    })
}

```

</div>

<div dir='rtl'>از آنجا که می‌خواهیم این میان‌افزار روی هر درخواست دریافتی اعمال شود، باید آن را قبل اینکه درخواست به servemux ما برسد، اجرا کنیم. می‌خواهیم جریان کنترل در برنامه ما به این شکل باشد:</div>

<div dir='rtl'>برای انجام این کار، باید تابع میان‌افزار commonHeaders servemux ما را دربرگیرد. بیایید فایل routes.go را به‌روزرسانی کنیم تا دقیقاً همین کار را انجام دهد:</div>

<div dir='ltr'>

**File: cmd/web/routes.go**

```

package main

import "net/http"

// Update the signature for the routes() method so that it returns a
// http.Handler instead of *http.ServeMux.
func (app *application) routes() http.Handler {
    mux := http.NewServeMux()

    fileServer := http.FileServer(http.Dir("./ui/static/"))
    mux.Handle("GET /static/", http.StripPrefix("/static", fileServer))
    
    mux.HandleFunc("GET /{$}", app.home)
    mux.HandleFunc("GET /snippet/view/{id}", app.snippetView)
    mux.HandleFunc("GET /snippet/create", app.snippetCreate)
    mux.HandleFunc("POST /snippet/create", app.snippetCreatePost)

    // Pass the servemux as the 'next' parameter to the commonHeaders middleware.
    // Because commonHeaders is just a function, and the function returns a
    // http.Handler we don't need to do anything else.
    return commonHeaders(mux)
}

```

</div>

<div dir='rtl'>مهم: اطمینان حاصل کنید که امضای متد routes() را به‌روزرسانی کرده‌اید تا یک http.Handler برگرداند، در غیر این صورت با خطای زمان کامپایل مواجه خواهید شد.</div>

<div dir='rtl'>همچنین باید سریعاً کد هندلر home خود را به‌روزرسانی کنیم تا خط w.Header().Add("Server", "Go") را حذف کنیم، در غیر این صورت این هدر را دو بار در پاسخ‌های صفحه اصلی اضافه خواهیم کرد.</div>

<div dir='ltr'>

**File: cmd/web/handlers.go**

```

package main

...

func (app *application) home(w http.ResponseWriter, r *http.Request) {
    snippets, err := app.snippets.Latest()
    if err != nil {
        app.serverError(w, r, err)
        return
    }

    data := app.newTemplateData(r)
    data.Snippets = snippets

    app.render(w, r, http.StatusOK, "home.tmpl", data)
}

...

```

</div>

<div dir='rtl'>پیش بروید و این را امتحان کنید. برنامه را اجرا کنید و سپس یک پنجره ترمینال باز کنید و سعی کنید با curl درخواست‌هایی ارسال کنید. باید ببینید که هدرهای امنیتی اکنون در هر پاسخ گنجانده شده‌اند.</div>

### اطلاعات تکمیلی

#### جریان کنترل

<div dir='rtl'>مهم است بدانید که وقتی آخرین هندلر در زنجیره برمی‌گردد، کنترل در جهت معکوس به بالای زنجیره برمی‌گردد. بنابراین وقتی کد ما در حال اجراست، جریان کنترل در واقع به این شکل است:</div>

<div dir='rtl'>در هر هندلر میان‌افزار، کدی که قبل از next.ServeHTTP() می‌آید در مسیر پایین زنجیره اجرا می‌شود، و هر کدی که بعد از next.ServeHTTP() — یا در یک تابع deferred — می‌آید در مسیر برگشت به بالا اجرا خواهد شد.</div>

#### برگشت‌های زودهنگام

<div dir='rtl'>نکته دیگری که باید ذکر شود این است که اگر شما return را در تابع میان‌افزار خود قبل از فراخوانی next.ServeHTTP() صدا بزنید، زنجیره متوقف خواهد شد و کنترل به بالا برمی‌گردد.</div>

<div dir='rtl'>به عنوان مثال، یک مورد استفاده رایج برای برگشت‌های زودهنگام، میان‌افزار احراز هویت است که فقط در صورتی اجازه ادامه اجرای زنجیره را می‌دهد که یک بررسی خاص موفقیت‌آمیز باشد. به عنوان مثال:</div>

<div dir='rtl'>ما از این الگوی 'برگشت زودهنگام' بعداً در کتاب برای محدود کردن دسترسی به بخش‌های خاصی از برنامه‌مان استفاده خواهیم کرد.</div>

#### رفع اشکال مسائل CSP

<div dir='rtl'>در حالی که هدرهای CSP عالی هستند و قطعاً باید از آنها استفاده کنید، ارزش گفتن دارد که من ساعت‌های زیادی را صرف رفع اشکال مشکلات کرده‌ام، فقط برای اینکه در نهایت متوجه شوم که یک منبع یا اسکریپت حیاتی توسط قوانین CSP خودم مسدود شده است 🤦.</div>

<div dir='rtl'>اگر روی پروژه‌ای کار می‌کنید که از هدرهای CSP استفاده می‌کند، مانند این پروژه، توصیه می‌کنم ابزارهای توسعه‌دهنده مرورگر وب خود را در دسترس داشته باشید و عادت کنید که اگر با مشکلات غیرمنتظره‌ای مواجه شدید، لاگ‌ها را زود بررسی کنید. در Firefox، هر منبع مسدود شده به عنوان یک خطا در لاگ‌های کنسول نمایش داده می‌شود — مشابه این:</div>
