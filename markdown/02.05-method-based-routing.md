# فصل 2.5.

## مسیریابی مبتنی بر روش

<div dir='rtl'>در ادامه، بیایید با رعایت اصول خوب HTTP، برنامه خود را محدود کنیم تا فقط به درخواست‌هایی با روش HTTP مناسب پاسخ دهد.</div>

<div dir='rtl'>همانطور که در ساخت برنامه خود پیش می‌رویم، هندلرهای home، snippetView و snippetCreate فقط اطلاعات را بازیابی کرده و صفحات را به کاربر نمایش می‌دهند، بنابراین منطقی است که این هندلرها را به درخواست‌های GET محدود کنیم.</div>

<div dir='rtl'>برای محدود کردن یک مسیر به یک روش HTTP خاص، می‌توانید الگوی مسیر را با روش HTTP مورد نیاز هنگام اعلام آن پیشوند کنید، به این صورت:</div>

<div dir='ltr'>

**File: main.go**

```

package main

...

func main() {
    mux := http.NewServeMux()
    // Prefix the route patterns with the required HTTP method (for now, we will
    // restrict all three routes to acting on GET requests).
    mux.HandleFunc("GET /{$}", home)
    mux.HandleFunc("GET /snippet/view/{id}", snippetView)
    mux.HandleFunc("GET /snippet/create", snippetCreate)

    log.Print("starting server on :4000")

    err := http.ListenAndServe(":4000", mux)
    log.Fatal(err)
}

```

</div>

<div dir='rtl'>توجه: روش‌های HTTP در الگوهای مسیر حساس به حروف بزرگ و کوچک هستند و باید همیشه با حروف بزرگ نوشته شوند، به دنبال آن حداقل یک کاراکتر فاصله (هم فاصله‌ها و هم تب‌ها مناسب هستند) قرار گیرد. شما فقط می‌توانید یک روش HTTP را در هر الگوی مسیر قرار دهید.</div>

<div dir='rtl'>همچنین شایان ذکر است که وقتی یک الگوی مسیر را که از روش GET استفاده می‌کند ثبت می‌کنید، هم GET و هم HEAD را مطابقت می‌دهد. همه روش‌های دیگر (مانند POST، PUT و DELETE) نیاز به مطابقت دقیق دارند.</div>

<div dir='rtl'>بیایید این تغییر را با استفاده از curl برای ارسال چند درخواست به برنامه خود آزمایش کنیم. اگر شما هم در حال دنبال کردن هستید، با ارسال یک درخواست GET معمولی به http://localhost:4000/ شروع کنید، به این صورت:</div>

<div dir='rtl'>پاسخ اینجا خوب به نظر می‌رسد. می‌توانیم ببینیم که مسیر ما هنوز کار می‌کند و یک وضعیت 200 OK و یک بدنه پاسخ Hello from Snippetbox دریافت می‌کنیم، درست مثل قبل.</div>

<div dir='rtl'>همچنین می‌توانید یک درخواست HEAD برای همان URL ارسال کنید. باید ببینید که این نیز به درستی کار می‌کند و فقط هدرهای پاسخ HTTP را برمی‌گرداند و هیچ بدنه پاسخی ندارد.</div>

<div dir='rtl'>در مقابل، بیایید یک درخواست POST به http://localhost:4000/ ارسال کنیم. روش POST برای این مسیر پشتیبانی نمی‌شود، بنابراین باید یک پاسخ خطا مشابه این دریافت کنید:</div>

<div dir='rtl'>توجه: پرچم -d در curl برای اعلام هر داده POST HTTP که می‌خواهید در بدنه درخواست قرار دهید استفاده می‌شود. در فرمان بالا از -d "" استفاده می‌کنیم، که به این معنی است که بدنه درخواست خالی خواهد بود، اما درخواست همچنان با روش HTTP POST (به جای روش پیش‌فرض GET) ارسال خواهد شد.</div>

<div dir='rtl'>بنابراین این خیلی خوب به نظر می‌رسد. می‌توانیم ببینیم که servemux گو به طور خودکار یک پاسخ 405 Method Not Allowed برای ما ارسال کرده است، شامل یک هدر Allow که روش‌های HTTP را که برای URL درخواست پشتیبانی می‌شوند، فهرست می‌کند.</div>

### افزودن یک مسیر و هندلر فقط برای POST

<div dir='rtl'>بیایید همچنین یک هندلر جدید snippetCreatePost به کد خود اضافه کنیم، که بعداً برای ایجاد و ذخیره یک قطعه جدید در یک پایگاه داده استفاده خواهیم کرد. از آنجا که ایجاد و ذخیره یک قطعه یک عمل غیرقابل تکرار است که وضعیت سرور ما را تغییر می‌دهد، می‌خواهیم مطمئن شویم که این هندلر فقط به درخواست‌های POST عمل می‌کند.</div>

<div dir='rtl'>در مجموع، می‌خواهیم هندلر و مسیر چهارم ما به این صورت باشد:</div>

<div dir='rtl'>بیایید کد لازم را به فایل main.go خود اضافه کنیم، به این صورت:</div>

<div dir='ltr'>

**File: main.go**

```

package main

...

// Add a snippetCreatePost handler function.
func snippetCreatePost(w http.ResponseWriter, r *http.Request) {
    w.Write([]byte("Save a new snippet..."))
}

func main() {
    mux := http.NewServeMux()
    mux.HandleFunc("GET /{$}", home)
    mux.HandleFunc("GET /snippet/view/{id}", snippetView)
    mux.HandleFunc("GET /snippet/create", snippetCreate)
    // Create the new route, which is restricted to POST requests only.
    mux.HandleFunc("POST /snippet/create", snippetCreatePost)
    
    log.Print("starting server on :4000")

    err := http.ListenAndServe(":4000", mux)
    log.Fatal(err)
}

```

</div>

<div dir='rtl'>توجه داشته باشید که اعلام دو (یا بیشتر) مسیر جداگانه که روش‌های HTTP متفاوتی دارند اما الگوی یکسانی دارند، کاملاً مجاز است، مانند آنچه که در اینجا با "GET /snippet/create" و "POST /snippet/create" انجام می‌دهیم.</div>

<div dir='rtl'>اگر برنامه را مجدداً راه‌اندازی کنید و سعی کنید با استفاده از مسیر URL /snippet/create درخواست‌هایی ارسال کنید، باید اکنون پاسخ‌های متفاوتی بسته به روش درخواست که استفاده می‌کنید، ببینید.</div>

### اطلاعات اضافی

#### اولویت روش

<div dir='rtl'>قانون الگوی خاص‌تر برنده می‌شود نیز در صورتی که الگوهای مسیر به دلیل یک روش HTTP همپوشانی داشته باشند، اعمال می‌شود.</div>

<div dir='rtl'>مهم است که بدانید یک الگوی مسیری که شامل یک روش نیست — مانند "/article/{id}" — با درخواست‌های HTTP با هر روشی مطابقت خواهد داشت. در مقابل، مسیری مانند "POST /article/{id}" فقط با درخواست‌هایی که روش POST دارند مطابقت خواهد داشت. بنابراین اگر مسیرهای همپوشانی "/article/{id}" و "POST /article/{id}" را در برنامه خود اعلام کنید، مسیر "POST /article/{id}" اولویت خواهد داشت.</div>
