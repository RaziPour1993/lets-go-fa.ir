## طراحی مدل پایگاه داده

<div dir='rtl'>در این فصل، ما قصد داریم یک مدل پایگاه داده برای پروژه‌مان طراحی کنیم.</div>

<div dir='rtl'>اگر با اصطلاح مدل راحت نیستید، می‌توانید آن را به عنوان یک لایه سرویس یا لایه دسترسی به داده در نظر بگیرید. هر اصطلاحی که ترجیح می‌دهید، ایده این است که ما کد کار با MySQL را در یک پکیج جداگانه از بقیه برنامه کپسوله خواهیم کرد.</div>

<div dir='rtl'>فعلاً، ما یک مدل پایگاه داده اسکلتی ایجاد می‌کنیم و آن را با مقداری داده آزمایشی برمی‌گردانیم. خیلی کار نخواهد کرد، اما می‌خواهم قبل از اینکه وارد جزئیات پرس‌وجوهای SQL شویم، الگو را توضیح دهم.</div>

<div dir='rtl'>خوب به نظر می‌رسد؟ پس بیایید یک دایرکتوری جدید internal/models ایجاد کنیم که حاوی یک فایل snippets.go است:</div>

![04.05-01.png](assets/img/04.05-01.png)

<div dir='rtl'>به یاد داشته باشید: از دایرکتوری internal برای نگهداری کدهای جانبی غیر مختص برنامه استفاده می‌شود که می‌تواند بالقوه مجدداً استفاده شود. یک مدل پایگاه داده که می‌تواند در آینده توسط برنامه‌های دیگر (مانند یک برنامه رابط خط فرمان) استفاده شود، در این دسته قرار می‌گیرد.</div>

<div dir='rtl'>بیایید فایل internal/models/snippets.go را باز کنیم و یک ساختار Snippet جدید برای نمایش داده‌های یک قطعه کد منفرد، به همراه یک نوع SnippetModel با متدهایی برای دسترسی و دستکاری قطعه‌های کد در پایگاه داده‌مان اضافه کنیم. به این صورت:</div>

### استفاده از SnippetModel

<div dir='rtl'>برای استفاده از این مدل در هندلرهایمان، نیاز داریم یک ساختار SnippetModel جدید در تابع main() خود ایجاد کنیم و سپس آن را به عنوان یک وابستگی از طریق ساختار application تزریق کنیم - درست مانند کاری که با سایر وابستگی‌هایمان انجام داده‌ایم.</div>

<div dir='rtl'>به این صورت:</div>

<div dir='ltr'>

**File: cmd/web/main.go**

```

package main

import (
    "database/sql"
    "flag"
    "log/slog"
    "net/http"
    "os"

    // Import the models package that we just created. You need to prefix this with
    // whatever module path you set up back in chapter 02.01 (Project Setup and Creating
    // a Module) so that the import statement looks like this:
    // "{your-module-path}/internal/models". If you can't remember what module path you 
    // used, you can find it at the top of the go.mod file.
    "snippetbox.letsgofa.net/internal/models" 

    _ "github.com/go-sql-driver/mysql"
)

// Add a snippets field to the application struct. This will allow us to
// make the SnippetModel object available to our handlers.
type application struct {
    logger   *slog.Logger
    snippets *models.SnippetModel
}

func main() {
    addr := flag.String("addr", ":4000", "HTTP network address")
    dsn := flag.String("dsn", "web:pass@/snippetbox?parseTime=true", "MySQL data source name")
    flag.Parse()

    logger := slog.New(slog.NewTextHandler(os.Stdout, nil))

    db, err := openDB(*dsn)
    if err != nil {
        logger.Error(err.Error())
        os.Exit(1)
    }
    defer db.Close()

    // Initialize a models.SnippetModel instance containing the connection pool
    // and add it to the application dependencies.
    app := &application{
        logger:   logger,
        snippets: &models.SnippetModel{DB: db},
    }

    logger.Info("starting server", "addr", *addr)

    err = http.ListenAndServe(*addr, app.routes())
    logger.Error(err.Error())
    os.Exit(1)
}
```

### اطلاعات تکمیلی

#### مزایای این ساختار

<div dir='rtl'>اگر یک قدم به عقب بردارید، ممکن است بتوانید چند مزیت از راه‌اندازی پروژه به این روش را ببینید:</div>

<div dir='rtl'>جداسازی تمیز دغدغه‌ها وجود دارد. منطق پایگاه داده ما به هندلرهایمان متصل نخواهد بود، که به این معنی است که مسئولیت‌های هندلر محدود به موارد HTTP است (یعنی اعتبارسنجی درخواست‌ها و نوشتن پاسخ‌ها). این در آینده نوشتن تست‌های واحد متمرکز و دقیق را آسان‌تر خواهد کرد.</div>

<div dir='rtl'>با ایجاد یک نوع SnippetModel سفارشی و پیاده‌سازی متدها روی آن، توانسته‌ایم مدل خود را به یک شیء منظم و کپسوله شده تبدیل کنیم که می‌توانیم به راحتی آن را مقداردهی اولیه کرده و سپس به عنوان یک وابستگی به هندلرهایمان منتقل کنیم. باز هم، این باعث می‌شود کد قابل نگهداری‌تر و قابل آزمایش‌تر شود.</div>

<div dir='rtl'>از آنجایی که اعمال مدل به عنوان متدهایی روی یک شیء تعریف شده‌اند - در مورد ما SnippetModel - این فرصت وجود دارد که یک رابط ایجاد کنیم و آن را برای اهداف تست واحد شبیه‌سازی کنیم.</div>

<div dir='rtl'>و در نهایت، ما کنترل کامل بر روی اینکه کدام پایگاه داده در زمان اجرا استفاده می‌شود را داریم، فقط با استفاده از پرچم خط فرمان -dsn.</div>
